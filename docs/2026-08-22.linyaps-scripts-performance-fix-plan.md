## Phase A：约束单一化（对应问题 2、4）

### A.1 新建权威约束 SKILL

新建 `skills/linyaps-packaging.constraints/SKILL.md`，作为**唯一**约束权威，内容涵盖：

- `${PREFIX}` 安装目录约束（原散落于 `agent.md:213-220` / `for-multica/agent.md` / `source-updater SKILL`）
- 构建约束（`@MAX_BUILD_ATTEMPTS@` / `@BUILD_TIMEOUT_SEC@` 语义）
- `<pack_repo_dir>` 持久化与缓存复用约束
- `${tag}` 路径即时解析单一规则
- 修改日志格式约束

命名贴合本仓库 `linyaps-*` / `linglong-*` 风格：`linyaps-packaging.constraints`。

### A.2 agent 一次载入

两个 agent（`agents/linyaps-packaging-runner.agent.md`、`for-multica/agent.md`）在
「Phase 1 初始化」末尾通过 `skill()` 一次载入该 SKILL：

```
result = skill("linyaps-packaging.constraints", {})
```

后续所有步骤引用约束时，只引用「已载入的约束 SKILL」，不在正文重复约束细节。

### A.3 子 SKILL 重复段 → 引用

`skills/linglong-source-updater/SKILL.md`、`skills/linglong-binary-runner/SKILL.md` 中
与权威约束重复的段落收敛为一行引用：

```
> 安装目录 / 构建 / 路径等约束见 `skill("linyaps-packaging.constraints")`，本 SKILL 不再重复。
```

## Phase B：版本归一化 + 校验给修复（对应问题 1、6）

### B.1 update-linglong-yaml.py 增加版本归一化

在 `update-linglong-yaml.py` 引入 `normalize_version()`：

1. 取前 4 个数字段（忽略非数字尾部，如 `-1`、`_alpha`、`rc`）。
2. 不足 4 段时补 `.0` 到 4 段。
3. 每段去除前导 `0`（但保留单 `0`），避免 `3.0.23.02` 这类校验拒绝。
   - 例：`2.0` → `2.0.0.0`；`3.0.23` → `3.0.23.0`；`2.04-alpha` → `2.4.0.0`；
     `5.7.21.0-1` → `5.7.21.0`。
4. 同时**写入顶层 `version`**（与 `package.version` 保持一致），消除
   `validate` 的 `top-level version must be a single digit` 报错。

`normalize_version` 需与 `validate-linglong-yaml.py` 的 `PACKAGE_VERSION_RE`
（`a.b.c.d` 纯数字）对齐，从源头避免回环。

### B.2 validate-linglong-yaml.py 输出修复命令

- 当仅因版本格式（`package.version` / 顶层 `version`）失败时，输出一行可执行建议：
  ```
  # 建议修复：
  python3 skills/linglong-source-updater/scripts/update-linglong-yaml.py --path=<dir> --version=<归一化后的版本> ...
  ```
- 归一化逻辑与 B.1 共享同一实现（可抽公共函数），保证契约一致。

## Phase C：路径参数收口 + 接口统一（对应问题 3、5、7）

### C.1 收敛 `find_source_project_dir` 语义

统一所有 `common.sh` 中的 `find_source_project_dir` 为**精确匹配**
（`CI_ll_<pkg>` / `<pkg>`，排除子串模糊命中），与
`skills/linglong-source-updater/scripts/common.sh:457-490` 的 Issue-60 精确语义一致。

### C.2 删除 search 散文两 agent 步骤 5

`for-multica/agent.md:294-337` 与 `agents/linyaps-packaging-runner.agent.md` 步骤 5 中
「最后模糊搜索包含 pkgName 的目录」的描述删除，改为「按精确规则定位（见
`skills/linglong-binary-runner/scripts/common.sh` / `linglong-source-updater/scripts/common.sh`）」，
避免引导低效模糊搜索。

### C.3 `${tag}` 解析仅一次

在 agent Phase 1 统一执行 `${tag}` 解析并存储结果，删除 `for-multica/agent.md:95-101` 的
重复强调，只保留一条规则引用。

### C.4 端点收口

- `dispatch.sh:35`：`CONFIG_FILE` 不再硬编码默认 `for-multica/agent-config.json`，收到
  `--config` / `--agent-config-path` 未提供时要求显式传入或从环境变量 `AGENT_CONFIG_PATH` 读取。
- webhook / S3 端点移入配置（`agent-config.json` 的 `global` 区段），`status_upload*.sh` 与
  `precheck.sh` 从配置读取，消除硬编码。

## 附：风险与说明

- `common.sh` 有 5+ 份且彼此版本不同（模糊 vs 精确、有无 build lock、有无 write_fix_log）。
  完整合并为一个库风险较高，本计划在 C.1 阶段**仅统一 `find_source_project_dir` 语义**
  而非强合所有副本，以控制回归风险；后续可单独立项合并。
- 修改日志格式约束（`agent.md` 末尾）已在 A 中纳入权威约束 SKILL，作为唯一出处。
