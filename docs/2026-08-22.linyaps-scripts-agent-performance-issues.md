# linyaps-packaging-scripts-running-skill Agent 高 Token 根因分析报告

- 日期：2026-08-22
- 分析对象：`linyaps-packaging-scripts-running-skill`（`linyaps-packaging-runner` agent 与其 5 个子 SKILL）
- 基线：`examples/2026-08-22.token-usage-analyze.md`（token 用量统计）与平行仓库
  `debian-rules-to-linyaps-rules` 的分析/整改文档
- 范围：全量覆盖 A(约束) + B(版本/校验) + C(路径/接口)，仅产出文档，不改代码

## 背景

本文档将高 token 根因（来源 `token-usage-analyze.md`）逐项映射到本仓库的**具体代码位置**，
确认每一项是否真实存在，为 `2026-08-22.linyaps-scripts-performance-fix-plan.md` 的整改方案提供依据。

## 根因清单与代码映射

### 问题 1：版本无归一化 → 校验回环（最高收益 A++）

- **现象**：`package.version` 未归一化导致 `update` 写出的值与 `validate` 期望的
  `a.b.c.d` 纯数字四位格式不一致，LLM 反复在「更新 → 校验失败 → 重新更新」之间回环空转。
- **update 侧无归一化**：
  `skills/linglong-source-updater/scripts/update-linglong-yaml.py:133`
  ```python
  data["package"]["version"] = new_version   # 直接写原值，不做归一化/补 0/去尾
  ```
  - 且 `update-linglong-yaml.py` **不写顶层 `version`**（仅写 `package.version`）。
- **validate 侧契约不一致**：
  `skills/linglong-source-updater/scripts/validate-linglong-yaml.py`
  - `:59` `PACKAGE_VERSION_RE = re.compile(r'^\d+\.\d+\.\d+\.\d+$')`（要求 4 段纯数字）
  - `:60` `TOPLEVEL_VERSION_RE = re.compile(r'^\d+$')`（要求顶层 version 为**单个**数字）
  - `:116-117` 顶层 version 必须匹配单个数字
  - `:128-129` `package.version` 必须匹配 `a.b.c.d`
  - `:204-208` 仅输出错误文本，**不给出可执行的修复命令**
- **后果**：上游版本常形如 `2.0`、`3.0.23`、`2.04-alpha`、`5.7.21.0-1`，update 直接写入后
  validate 报错，两者契约无桥接，LLM 只能靠猜补 0 / 去尾，形成高 token 回环。

### 问题 2：约束多文档重复放大固定上下文（A）

- **现象**：同一约束在多处重复，每次载入都重复计入 token。
- `${PREFIX}` 安装目录约束重复出现在：
  - `agents/linyaps-packaging-runner.agent.md:213-220`
  - `for-multica/agent.md:665-666`
  - `skills/linglong-source-updater/SKILL.md:38-42, 191`
- 构建设约束（`@MAX_BUILD_ATTEMPTS@` / `@BUILD_TIMEOUT_SEC@`）重复出现在两个 agent 与
  多个 SKILL 中。

### 问题 3：`search` 散文 / 模糊定位（A）

- **现象**：agent/SKILL 教模型使用模糊搜索定位项目目录，散文式说明重复度高。
- `skills/linglong-binary-runner/scripts/common.sh:375`（与根 `scripts/common.sh:375` 相同）
  ```bash
  found=$(find "$root" -maxdepth 2 -type d -name "*${pkg_name}*" ...)   # 模糊 *pkg*
  ```
- 两 agent 步骤 5 均引导「最后模糊搜索包含 `pkgName` 的目录」。

### 问题 4：`${tag}` 重复强调（A）

- **现象**：低收益、高重复的强调多次出现，占固定上下文。
  - `agents/linyaps-packaging-runner.agent.md:70`（`${tag}` 即时解析规则）
  - `for-multica/agent.md:95-101`（5 条 `${tag}` 解析强制性说明）

### 问题 5：多份 `common.sh` 近重复 + 语义分歧（B）

- **现象**：几乎相同的共享库存在 5+ 份，且 `find_source_project_dir` 语义分歧，造成维护
  与上下文浪费。
  - `scripts/common.sh`（469 行，模糊 `find_source_project_dir`）
  - `skills/linglong-binary-runner/scripts/common.sh`（469 行，与根**逐字节相同**）
  - `skills/linglong-source-updater/scripts/common.sh`（551 行，**精确** `find_source_project_dir` + build lock）
  - `skills/linyaps-packaging-report/scripts/common.sh`（404 行，模糊）
  - `skills/linyaps-packaging-precheck/scripts/common.sh`（404 行，模糊）
  - `skills/linyaps-multica-packer-dispatch/scripts/common.sh`（486 行，multica 专属 + 模糊）
- **语义分歧**：`find_source_project_dir` 在 source-updater 中为精确匹配
  （`-name "CI_ll_${pkg}" -o -name "$pkg"`），在其他副本中为模糊 `-name "*${pkg}*"`。

### 问题 6：校验不给可执行修复（B）

- **现象**：`validate-linglong-yaml.py` 只报错文本，不给出修复命令，LLM 需自行推导。
- `skills/linglong-source-updater/scripts/validate-linglong-yaml.py:204-208` 仅打印错误。

### 问题 7：硬编码端点字符串（低危 C）

- **现象**：webhook / S3 端点硬编码在脚本中，跨文件重复，且变更需改多处。
  - `skills/linyaps-packaging-precheck/scripts/precheck.sh:189`（webhook URL）
  - `skills/linyaps-packaging-report/scripts/status_upload.sh:110`（webhook URL）
  - `skills/linyaps-packaging-report/scripts/status_upload_initOnly.sh:111`（init webhook URL）
  - `skills/linyaps-multica-packer-dispatch/scripts/dispatch.sh:35`（默认 config 硬编码）
- 注：`precheck.sh:36,172,189` 与 `dispatch.sh:35` 已消费 `--agent-config-path`，非参数漂移。

## 明确排除（本仓库不存在）

- **拼写错误**：`skills/linglong-source-updater/references/` 命名正确（无 `refence`/`referance`）。
- **`agent_config_path` 参数漂移**：`dispatch.sh`、`precheck.sh`、两 `run_tasks.sh` 均已消费
  该参数，不存在「传了但脚本不用」的问题。

写入 + 校验给修复命令），其次为问题 2（约束单一化）。整改优先级建议 C→B→A。
